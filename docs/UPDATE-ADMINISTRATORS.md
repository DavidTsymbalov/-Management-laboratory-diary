# Подключить администраторов к существующему сайту

Интерфейс и код готовы. Для работы новой роли нужно применить обновление именно к проекту `pnpanexhudlalavcevck`. Ученики, баллы, достижения и аккаунт преподавателя сохраняются.

## 1. Обновить базу

Откройте [SQL Editor Supabase](https://supabase.com/dashboard/project/pnpanexhudlalavcevck/sql/new).

Вставьте **весь** файл [`supabase/migrations/202611050001_administrators.sql`](../supabase/migrations/202611050001_administrators.sql) и нажмите **Run**. Этот файл можно выполнить повторно: существующие записи не удаляются.

Первую миграцию `202611030001_classroom.sql` заново выполнять не нужно.

## 2. Обновить серверную функцию

В [Edge Functions](https://supabase.com/dashboard/project/pnpanexhudlalavcevck/functions) откройте существующую **manage-students**, затем редактор кода. Замените код содержимым [`supabase/functions/manage-students/index.ts`](../supabase/functions/manage-students/index.ts) и опубликуйте обновление.

Сохраните существующую настройку `Verify JWT with legacy secret`: выключено. Проверку пользователя и его прав выполняет сама функция через `auth.getUser` и таблицы ролей. Секретные ключи в сайт добавлять не нужно.

Если официальный Supabase CLI уже авторизован, функцию также можно опубликовать командой:

```sh
supabase functions deploy manage-students --project-ref pnpanexhudlalavcevck
```

Применение SQL и публикация функции — два отдельных шага. Одна публикация сайта на GitHub Pages их не выполняет.

## 3. Создать администратора

1. На сайте выберите **Вход для преподавателя**. Войдите с прежним логином `teacher` и своим паролем.
2. Откройте **Администраторы → Добавить администратора**.
3. Укажите имя, отдельный логин и пароль от 8 до 128 символов. Email не нужен.
4. Передайте данные этому администратору. Он входит через **Администратор**, а не через вход преподавателя.

Администратор видит весь класс, создаёт и удаляет учеников, меняет их пароли, выдаёт и списывает баллы, выдаёт достижения, смотрит статистику. Создавать, удалять и менять пароли администраторов может только преподаватель. Ни один из этих кабинетов не позволяет менять учётную запись преподавателя.

## Проверка после публикации

На отдельных аккаунтах проверьте вход преподавателя, ученика и администратора. В кабинете администратора нет раздела управления администраторами. Проверка прав действует также в базе и серверной функции, а не только скрывает кнопку.

Существующий вход преподавателя и ученика сохранён. Если SQL ещё не применён, открытие списка администраторов покажет сообщение о недоступности раздела, а существующие кабинеты продолжат работать.
