# Общая база Supabase

Проект: `pnpanexhudlalavcevck`. Адрес и публичный ключ уже заданы в `src/lib/supabase.ts`. Secret/service_role key нельзя добавлять в клиент, GitHub или переменные `NEXT_PUBLIC_*`.

Для уже настроенного проекта см. [подключение администраторов](UPDATE-ADMINISTRATORS.md).

## 1. Таблицы

Откройте [SQL Editor](https://supabase.com/dashboard/project/pnpanexhudlalavcevck/sql/new), создайте запрос, вставьте **весь** файл `supabase/migrations/202611030001_classroom.sql` и нажмите **Run**. Запрос выполняется один раз в новом пустом проекте. После успеха появятся таблицы `teachers`, `students`, `achievements`, политики доступа RLS и функции начисления баллов.

Затем выполните добавочную миграцию `supabase/migrations/202611050001_administrators.sql` для роли администратора. В существующем проекте выполняйте только её, без повторного создания таблиц первой миграцией.

## 2. Аккаунт учителя

На сайте учитель входит с логином **`teacher`** и своим паролем. Личная почта и подтверждение по письму не нужны. Для встроенной авторизации Supabase логин преобразуется во внутренний адрес. Этот адрес не является почтовым ящиком и не показывается пользователям сайта.

В Supabase откройте **Authentication → Users → Add user → Create new user**. В поле Email вставьте этот технический идентификатор:

```text
t-1057a9604e04b274da5a4de0c8f4b4868d9b230989f8c8c6@teachers.management-laboratory.invalid
```

Задайте новый сложный пароль минимум из 8 символов. Включите **Auto Confirm User**. Пароль сохраните у себя: передавать его разработчику не нужно. Старый демонстрационный пароль больше не используется.

В SQL Editor выполните файл **`supabase/setup-teacher.sql`**. В результате должна появиться **одна строка**. Если строк нет, проверьте, что пользователь создан именно с указанным техническим идентификатором. Для другого логина нужен другой идентификатор — его вычисляет `teacherEmail` в `src/lib/student-identity.ts`; обычная замена текста `teacher` в форме создания аккаунта не подойдёт.

В **Authentication → Sign In / Providers** отключите **Allow new users to sign up**. Email/password должен оставаться включённым. Административная функция продолжит создавать учеников. Роль учителя назначается только записью в `teachers` через доверенный SQL Editor, а не метаданными пользователя.

## 3. Функция управления учениками

Функция позволяет создавать аккаунты учеников, задавать новые пароли и удалять их без раскрытия административного ключа в браузере.

1. Откройте **Edge Functions → Deploy a new function → Via Editor**.
2. Назовите функцию **`manage-students`**.
3. Вставьте код из `supabase/functions/manage-students/index.ts` вместо примера и опубликуйте.
4. В настройках функции отключите **Verify JWT with legacy secret** / **Enforce JWT verification**, если включено. Проверка JWT выполняется внутри функции через `auth.getUser`, затем проверяется запись в `teachers` или `admins`. Управление администраторами всегда требует запись в `teachers`. Это поддерживает новые ключи подписи Supabase.

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` предоставляются серверной функции автоматически. Не копируйте административный ключ в сайт. Не удаляйте проверки `auth.getUser` и таблиц ролей.

Альтернатива — официальный CLI из папки проекта:

```bash
npx supabase login
npx supabase functions deploy manage-students --project-ref pnpanexhudlalavcevck
```

Настройка проверки токена указана в `supabase/config.toml`. Все операции внутри функции требуют действующего пользовательского JWT и роли преподавателя или администратора; управление администраторами требует именно преподавателя. Одного Publishable key недостаточно.

## 4. Публикация и проверка

После шагов 1–3 отправьте новую версию на GitHub и дождитесь успешного **Deploy GitHub Pages**.

1. Войдите в кабинет учителя с логином **`teacher`** и новым паролем. Технический адрес вводить на сайте не нужно.
2. Добавьте `Тестовый Ученик | пробный-пароль-123`.
3. На другом устройстве без VPN войдите как ученик по ФИО и этому паролю.
4. Выдайте баллы и ачивку из кабинета учителя. Данные ученика обновляются при возврате во вкладку и каждые 15 секунд, пока она открыта.
5. Ученик видит только свои данные и своё место; полный класс доступен преподавателю и администратору.
6. После проверки удалите тестового ученика из кабинета учителя.

## Старые данные

В том же браузере и на том же домене, где раньше велись баллы, войдите в новый кабинет учителя и нажмите **«Перенести учеников с этого устройства»**. Переносятся ФИО, баллы, ачивки — до 30 учеников за раз. Совпадения по ФИО пропускаются с сообщением; существующие записи базы не перезаписываются.

Короткие старые пароли заменяются случайными. Данные входа показываются после создания аккаунтов: сохраните их и передайте каждому ученику только его пароль. После ухода со страницы прочитать сохранённые пароли нельзя, но учитель может задать новые. Исходное локальное хранилище не очищается автоматически.

Если данные остались на localhost, выполните перенос с локально запущенной новой версией (`npm run dev`) в том же браузере — она использует ту же общую базу.

## Проверки и ограничения

```bash
npm ci
npm run lint
npm run typecheck
npm test
GITHUB_PAGES=true npm run build
```

Тесты применяют реальную SQL-миграцию к PostgreSQL в памяти и проверяют права анонимного пользователя, ученика, преподавателя и администратора, запрет повышения роли, начисления, импорт и каскадное удаление. Отдельные тесты проверяют авторизацию Edge Function, согласованность ФИО при входе и откат незавершённого создания аккаунта. После настройки необходимо отдельно проверить живой проект.

Проект рассчитан на один общий класс. ФИО уникальны; для полных тёзок добавьте различающий суффикс и используйте его при входе. Пароли — от 8 до 128 символов. При равных баллах рейтинг упорядочен по ФИО и ID в PostgreSQL.

При ошибке сети сайт показывает ошибку и не записывает изменения в отдельную локальную копию. При пакетном добавлении показываются успешные записи и ошибки по остальным. Бесплатный Supabase может приостанавливаться после недели неактивности.

Официальные инструкции: [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [создание пользователей](https://supabase.com/docs/reference/javascript/auth-admin-createuser), [Edge Functions через панель](https://supabase.com/docs/guides/functions/quickstart-dashboard).
