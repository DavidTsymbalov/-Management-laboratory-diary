DIARY

MVP: баллы и ачивки класса
Командный проект №2

Проблема

  • Учителю сложно быстро вести учёт мотивации в классе
  • Ученик не видит прогресс в одном месте
  • Нужен простой MVP без тяжёлой админки

Гипотезы

  • H1. Ученикам важно видеть баллы и место в рейтинге
  • H2. Учителю удобнее выдавать баллы сразу нескольким
  • H3. Ачивки усиливают мотивацию сильнее, чем только цифры
  • H4. Статика в браузере достаточна для урока / демо

Процесс

  • Учитель → вход → кабинет
  • Добавляет учеников (ФИО | пароль)
  • Выбирает учеников → выдаёт баллы / ачивки
  • Ученик → вход → кабинет (баллы, место, ачивки)
  • Графики и рейтинг обновляются в том же браузере

Решение

  • Веб-кабинет класса (UI в духе Uncommon)
  • Роли: учитель / ученик
  • Баллы + ачивки + рейтинг + графики
  • Пиксельный переход и scramble-текст
  • Данные в localStorage + JSON-бэкап

Что внутри MVP

Учитель

  • класс (добавить / удалить)
  • выдача баллов и ачивок
  • сброс / выход
  • графики

Ученик

  • вход по ФИО + пароль
  • мои баллы
  • место в классе
  • мои ачивки

Стек

  • Next.js 16 (static export) · React · Tailwind v4
  • Сессия: sessionStorage · данные: localStorage
  • Шрифты: Aktiv Grotesk / Extended
  • Цвета: #080A0D · #E5DAC3
  • Хостинг: out/ → Reg.ru / FTP

Проверка и ОС

  • Собрали из подручного: Cursor + Next + статика
  • Итерации по фидбеку: UX выдачи, пароли, пиксели, UI
  • Контур ОС: демо → замечания → правки → снова демо
  • Дальше: форма багов / канал класса

Ограничения

  • Нет общего сервера: данные в браузере учителя
  • Актуальные баллы — на том же ПК или через бэкап
  • Для урока: ноутбук учителя + проектор — ок

Дальше

  • Выложить out/ на хостинг
  • Собрать ОС после реального урока
  • При росте класса — общий бэкенд
