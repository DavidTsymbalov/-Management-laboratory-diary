# Management Laboratory

Дневник класса: баллы, ачивки и личные кабинеты учителя и учеников.

Интерфейс — статический Next.js на GitHub Pages. Общие данные и авторизация — в Supabase. Учитель входит по логину и паролю, ученики — по ФИО (логину) и паролю. Личная почта не нужна: логины преобразуются во внутренние технические идентификаторы Supabase Auth. Пароли не хранятся в таблице учеников и не загружаются в браузер. Учитель видит весь класс, ученик — только свои данные и место в рейтинге.

## Настройка Supabase

Следуйте [инструкции настройки](docs/SUPABASE-SETUP.md): примените SQL-миграцию, создайте аккаунт учителя, назначьте ему права и опубликуйте функцию `manage-students`. До этих шагов облачные кабинеты не готовы к использованию.

Публичный адрес проекта и Publishable key уже заданы в `src/lib/supabase.ts`. Для другого проекта задайте `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` при сборке (пример — `.env.example`). Административный ключ `service_role` в сайт не добавлять.

## Локально

```bash
npm ci
npm run dev
```

Откройте http://localhost:3000. Локальный сайт использует ту же общую базу. Старые записи браузера доступны для переноса из кабинета учителя; автоматического возврата к локальному сохранению при сбое сети нет.

## GitHub Pages

1. Настройте Supabase по инструкции выше.
2. В репозитории откройте **Settings → Pages → Source → GitHub Actions**.
3. Отправьте изменения в `main`. Workflow проверит код, запустит тесты, соберёт и опубликует сайт.
4. Дождитесь успешного **Actions → Deploy GitHub Pages**. Адрес будет в результате deploy.

Ожидаемый адрес: https://davidtsymbalov.github.io/-Management-laboratory-diary/ .

```bash
GITHUB_PAGES=true npm run build
```

Результат — `out/` с `.nojekyll`. Путь сайта workflow получает из `configure-pages`, включая собственный домен. Для ручной сборки задайте `PAGES_BASE_PATH=/repository`; для корня домена — `PAGES_BASE_PATH=""`. Папки `out/` и `.next/` коммитить не нужно.

## Timeweb Cloud или FTP

Статическую версию можно разместить в Timeweb App Platform: Next.js, SSR выключен, сборка `npm run build`, директория `out`, без переменной `GITHUB_PAGES`. Серверные операции остаются в Supabase.

Для FTP выполните `npm run build` и загрузите содержимое `out/` в папку сайта. `npm start` не обслуживает статический экспорт: для предпросмотра нужен статический HTTP-сервер.
