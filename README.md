# Management Laboratory

Дашборд **баллов** и **ачивок** для командного проекта №2.

- Список учеников сначала пустой — учитель добавляет и удаляет сам
- Выдача баллов и ачивок из кабинета учителя
- Данные в браузере (+ бэкап JSON при необходимости)

Учётные данные учителя заданы в `src/data/seed.ts` и попадают в публичный JavaScript сборки. Текущий вход — локальная демонстрация, а не защищённая авторизация.

## Локально

```bash
npm install
npm run dev
```

Откройте http://localhost:3000

## Публикация на GitHub Pages

1. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. Загрузите изменения проекта в ветку `main`. Workflow `.github/workflows/deploy-github-pages.yml` выполнит установку зависимостей, lint, проверку TypeScript, статическую сборку и публикацию.
3. Дождитесь успешного завершения **Actions → Deploy GitHub Pages**. Повторный запуск доступен через **Run workflow**.

Для текущего репозитория ожидаемый адрес: https://davidtsymbalov.github.io/-Management-laboratory-diary/ . Фактический адрес будет в результате deploy.

Путь сайта берётся из настроек GitHub Pages через `configure-pages`, включая размещение на собственном домене. Вручную менять ссылки при переименовании репозитория не нужно.

Проверить сборку для текущего адреса локально:

```bash
GITHUB_PAGES=true npm run build
```

Для другого пути задайте `PAGES_BASE_PATH=/repository`; для корня домена — `PAGES_BASE_PATH=""`. Результат — папка `out/`, включая `.nojekyll`. Папки `out/` и `.next/` коммитить не нужно. Команда `npm start` не обслуживает статический экспорт: для предпросмотра нужен статический HTTP-сервер с `out/` по соответствующему пути.

## Сборка под Reg.ru (FTP)

```bash
npm run build
```

Папка `out/` — готовый сайт. Залейте **содержимое** `out/` в `public_html` (или папку сайта) через FTP-клиент Reg.ru.

Файл `.htaccess` уже лежит в сборке — нужен для Apache на shared-хостинге.

## Как пользоваться

1. Учитель → вход по логину/паролю из `seed.ts`
2. Начисляйте баллы, выдавайте ачивки
3. Ученик → ФИО + пароль → личный кабинет
4. Чтобы перенести данные: «Скачать бэкап» → на новом ПК «Загрузить бэкап»

## Важно про «память»

Данные живут **в браузере этого компьютера**.  
Для урока удобно вести учёт с ноутбука учителя (или один общий ПК) и показывать рейтинг на проекторе. Бэкап JSON — запасной способ не потерять таблицу.

На GitHub Pages это поведение сохраняется:

- Баллы, ученики и ачивки записываются в `localStorage` и сохраняются после перезагрузки в том же браузере, пока его данные не удалены.
- Состояние входа хранится в `sessionStorage` на время сессии вкладки.
- У каждого браузера и устройства своя копия данных. Ученик со своего телефона не увидит записи учителя с другого компьютера.
- При переходе с localhost на опубликованный домен данные автоматически не переносятся. Сначала скачайте JSON-бэкап, затем загрузите его на опубликованном сайте в нужном браузере. Бэкап содержит пароли учеников открытым текстом.
- GitHub Pages обслуживает статические файлы и сам по себе не добавляет базу данных или серверную авторизацию.

Для общего дневника нужна отдельная серверная часть либо облачный сервис базы данных и авторизации. Проверка роли учителя и разрешений на изменение баллов должна выполняться на стороне сервиса; пароли нельзя хранить в публичном коде или в открытом виде. Интерфейс при этом может остаться на GitHub Pages.
